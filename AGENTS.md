# Regras do Projeto — Pizzaria Brasa

## Missão

Criar um site profissional, rápido, responsivo e orientado a pedidos para a Pizzaria Brasa.

Antes de criar ou alterar qualquer parte do site, consultar:

1. BRIEFING-CLIENTE.md
2. DESIGN-SYSTEM.md
3. CHECKLIST-ENTREGA.md

Esses arquivos são a referência principal do projeto.

---

## 1. Objetivo principal

A principal conversão do site é:

**Pedir pizza pelo WhatsApp.**

CTA principal:

**Pedir pelo WhatsApp**

CTA secundário:

**Ver cardápio**

Toda decisão de UX deve facilitar essa jornada.

---

## 2. Público

O site é voltado principalmente para pessoas acessando pelo celular.

O visitante procura:

- pizza artesanal;
- cardápio;
- preços;
- facilidade para pedir;
- informações sobre entrega;
- horário;
- formas de pagamento;
- confiança na qualidade.

---

## 3. Prioridades

A ordem de prioridade é:

1. Clareza
2. Conversão
3. Experiência mobile
4. Apelo visual da comida
5. Confiança
6. Identidade visual
7. Acessibilidade
8. Performance
9. Facilidade de manutenção

---

## 4. UX

O visitante deve entender rapidamente:

- que se trata de uma pizzaria artesanal;
- quais são os principais sabores;
- como consultar o cardápio;
- como realizar o pedido;
- se existe entrega;
- horário de funcionamento;
- informações importantes para comprar.

Evitar:

- navegação confusa;
- excesso de texto;
- esconder preço quando ele estiver disponível;
- muitos cliques até o WhatsApp;
- informações importantes apenas no rodapé;
- elementos que dificultem o pedido.

---

## 5. Jornada de conversão

A jornada ideal é:

1. visitante entra no site;
2. entende imediatamente a proposta;
3. vê pizzas apetitosas;
4. consulta sabores e preços;
5. entende como funciona o pedido;
6. encontra informações de entrega;
7. clica em "Pedir pelo WhatsApp".

---

## 6. UI

Seguir o DESIGN-SYSTEM.md.

Direção visual:

**Artesanal contemporâneo**

O site deve transmitir:

- calor;
- sabor;
- preparo artesanal;
- proximidade;
- qualidade;
- vontade de consumir o produto.

Evitar:

- estética de aplicativo de tecnologia;
- excesso de azul ou roxo;
- aparência de fast-food genérico;
- excesso de cards;
- animações desnecessárias;
- estética genérica de site criado por IA.

---

## 7. Fotografias

A comida deve ser protagonista.

Priorizar imagens de:

- pizza recém-saída do forno;
- queijo;
- bordas assadas;
- massa;
- ingredientes;
- forno;
- preparo;
- mesa;
- compartilhamento.

As imagens devem parecer:

- realistas;
- apetitosas;
- quentes;
- próximas.

Evitar texto embutido nas imagens sempre que possível.

---

## 8. Cardápio

O cardápio deve ser fácil de consultar principalmente no celular.

Cada item pode apresentar:

- nome;
- ingredientes;
- preço;
- imagem;
- ação para pedir.

Nunca inventar preço em projeto real.

Se o cliente ainda não tiver fornecido o valor, usar:

**Preço a confirmar**

ou placeholder claramente identificado durante o desenvolvimento.

---

## 9. WhatsApp

O WhatsApp é a principal conversão do site.

O botão deve:

- ser fácil de encontrar;
- usar linguagem clara;
- funcionar corretamente;
- aparecer em momentos importantes da jornada.

Texto preferido:

**Pedir pelo WhatsApp**

Evitar:

- "Clique aqui";
- "Saiba mais";
- CTAs vagos.

---

## 10. Informações de entrega

Quando fornecidas pelo cliente, deixar claras informações como:

- bairros atendidos;
- taxa de entrega;
- retirada;
- tempo médio;
- pedido mínimo;
- formas de pagamento.

Nunca inventar essas informações.

---

## 11. Conteúdo

Nunca inventar:

- endereço;
- telefone;
- WhatsApp;
- preços;
- avaliações;
- depoimentos;
- anos de experiência;
- quantidade de clientes;
- certificações;
- tempo de entrega;
- taxa de entrega;
- formas de pagamento.

Quando faltar informação, usar placeholder explicitamente identificado.

---

## 12. Mobile First

Desenvolver primeiro pensando em smartphone.

Garantir:

- texto fácil de ler;
- botões grandes;
- CTA visível cedo;
- cardápio fácil de consultar;
- nenhuma rolagem horizontal;
- imagens responsivas;
- carregamento rápido;
- navegação simples.

---

## 13. Código

Priorizar:

- HTML semântico;
- CSS organizado;
- JavaScript simples;
- poucas dependências;
- facilidade de manutenção;
- componentes reutilizáveis quando necessário.

Evitar bibliotecas quando HTML, CSS ou JavaScript nativo forem suficientes.

---

## 14. Acessibilidade

Garantir:

- contraste adequado;
- foco visível;
- headings organizados;
- alt em imagens relevantes;
- links identificáveis;
- botões identificáveis;
- navegação por teclado.

---

## 15. Performance

Evitar:

- imagens muito pesadas;
- vídeos automáticos;
- scripts desnecessários;
- animações pesadas;
- fontes em excesso;
- bibliotecas sem necessidade.

O site deve carregar rapidamente em conexão móvel.

---

## 16. SEO local

Quando os dados reais estiverem disponíveis:

- usar nome da empresa;
- serviço/produto principal;
- cidade;
- bairro quando relevante;
- title adequado;
- meta description;
- informações comerciais consistentes.

Não fazer repetição artificial de palavras-chave.

---

## 17. Regra anti-template

Antes de considerar o visual concluído, perguntar:

"Se eu trocar apenas o nome Pizzaria Brasa pelo nome de outra pizzaria, o site continuaria parecendo exatamente o mesmo?"

Se a resposta for sim, falta personalização.

O projeto deve possuir identidade própria.

---

## 18. Antes de considerar concluído

Verificar:

- versão mobile;
- versão desktop;
- menu;
- cardápio;
- WhatsApp;
- links;
- preços;
- informações de entrega;
- ortografia;
- responsividade;
- acessibilidade;
- performance;
- dados do cliente;
- ausência de informações inventadas.

Se houver erro crítico, corrigir antes de publicar.
